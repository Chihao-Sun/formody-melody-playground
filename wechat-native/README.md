# Formody · 拨形见声 — 原生微信小程序

独立的微信小程序项目，开发者工具中的项目名为 `formody`。不是 `web-view` 外壳，不依赖网页业务域名；网站代码、线上网站与既有 web-view 草稿均未被改写。本目录可以直接导入微信开发者工具。

## 当前基线

迁移依据：2026-10-06 核对的 Sites 第 **51** 版，提交 `38ee25d3f9cb41dac9307d93bd7c91f1e6571ca6`。这是夕阳湖岸投石的当前网站，不是 GitHub 根目录较早的 38 秒 Ripple 版本。`provenance.json` 与 `baseline/` 保存可复核的公开源码快照，不包含私人讨论。

已迁移：原始湖面图片、低多边形石头、风中芦苇、透视涟漪、拖拽松手投石、水漂／高抛／转圈曲线、四块石头成章、稀有晶石、各落点乐器、原旋律与节奏、连续声部、聆听点水与多指按住、曲终停留、低头寻石、声音开场、静音、设置和原版五边形数学体验。原水声文件逐字节复用，署名保留在产品内和 [ATTRIBUTION.md](ATTRIBUTION.md)。

两端独立拥有触摸、硬件与页面生命周期逻辑。纯数学、物理及音符规则在本次快照中相同，并有差分测试。以后可以有独立玩法；不要用同步脚本直接覆盖已经调整过的小程序。

## 导入与运行

1. 从此分支下载或检出仓库，在微信开发者工具中导入 **`wechat-native/`**，不是仓库根目录。
2. `project.config.json` 的 `appid` 当前为 **`touristappid` 占位**，不是已注册的小程序。先用测试号／游客方式做支持范围内的本地调试；真实硬件、分享、预览／上传以注册账号与实际工具支持为准。
3. 替换为 **Formody 自己的 AppID**。可以复用现有公司的注册主体，但不要填另一个产品的 AppID、上传密钥或其他凭证。本仓库没有配置任何真实账号或密钥。
4. 本项目调试配置使用基础库 `3.10.0`；核心音频接口至少需要 `2.22.0`，以真实客户端能否提供所需节点为准。先在开发者工具编译，然后分别在 iPhone 与 Android 真机预览。
5. 页面和素材随代码包离线加载，没有登录、后端、网络请求、传感器上传、录音或麦克风权限。来源链接采用“复制链接”，不在小程序内用通用浏览器跳转。

```sh
cd wechat-native
npm test
npm run check
```

Node 22+，核心测试无需 npm 安装依赖。可选画布对照需要开发机器有 `skia-canvas`（本次使用）或可正常解码 PNG 的 `@napi-rs/canvas`：

```sh
FORMODY_CANVAS_MODULE=/path/to/skia-canvas node tests/render-parity.cjs
```

## 如实区分的原生适配

| 项目 | 原生实现与差异 |
| --- | --- |
| 画面 | 原 Canvas 绘制算法与图片复用；微信胶囊／状态栏不可移除，品牌和按钮移到其下，底部文字避开安全区。 |
| 手势 | 原释放前 110 ms 速度与全路径弧度规则；改接 Canvas 原生多指 touch 事件，取消事件不会投出。网页键盘快捷键不作为手机操作入口。 |
| 声音 | `wx.createWebAudioContext`，原音高、节拍、合成泛音、包络与水声。立体声以双增益／声道合并实现；没有卷积节点时使用滤波延迟尾音，**混响不承诺与网页完全相同**。静音键、系统音频路由与输出时延需真机检查。 |
| 震动 | `wx.vibrateShort` 轻／中／重档位，逐跳减弱、限频；不是网页任意毫秒时长。调用成功也不能证明马达真的震动，需体验验证；失败如实显示并降级。 |
| 倾斜 | `wx.startDeviceMotionListening` 与 `wx.onDeviceMotionChange`，读取弧度后按原网页角度灵敏度换算，校准初始姿态。横屏左右方向根据初始姿态推断，平放时存在歧义，需真机确认。当前玩法需要的是**姿态角**，不是把原始陀螺仪角速度当角度使用。 |
| 控制 | 设置中额外保留倾斜与减少动态效果的可关闭控制。自动读取系统减弱动画偏好没有作可靠性承诺。 |
| 生命周期 | 打开设置、切后台暂停音乐时钟、飞行与画面；恢复保持同一轮；卸载关闭音频／传感器／动画与计时器。 |

“存在接口”“调用被系统允许”“收到真实传感器数据”“产生真实手感”是不同状态；不能统称为已获得授权，也不保证每次有授权弹窗。拒绝或不可用不会挡住投石。姿态数据只在本机短时计算，不保存／上传；是否还需平台隐私声明和相关提审设置，应按注册 AppID 的控制台及比赛要求核对。

## 以后如何开发与同步

网站与小程序分别维护。网站改动不会自动变成原生小程序；每次涉及体验的改动，需要对应修改小程序并运行回归检查。数学／规则的共性可由差分测试守住，但硬件、触摸和渲染性能应独立验收。

仓库中 `formody-native-check.yml` 自动执行小程序测试和静态检查，不会上传或发布。未来配置独立 AppID、官方 CI 上传密钥、固定出口 IP 和真机验收门槛后，可以自动化**开发版上传**；审核、比赛提交与正式发布是另外的步骤，本次没有启用。正式代码许可证仍由负责人选择，未新增 LICENSE 或贡献开放承诺。
